# 安身 AnShen — 慈濟大型災害收容安置管理系統（演示原型）

> 2026-07-13 vibe coding 演示交付。單檔 `shelter/index.html`，零依賴、可離線、localStorage 持久化。
> 全新架構（未沿用 DRMS Widget 架構，Mason 明令）。人物與數據皆虛構。

## 一句話需求
慈濟會所（靜思堂/園區/聯絡處）啟用為大型災害收容處所時，把「**個案管理**（既有強項）×**空間管理**（總務處平時零能量）×**餐食物資供應**（零經驗）」整合為一套含工作流／資訊流／權限流的營運系統。

## 痛點 → 系統對應
| Mason 原話 | 系統回應 |
|---|---|
| 總務處完全沒有能量準備 | 「平時整備檢核表」＋空間平時建檔——平戰結合，開設申請以檢核表為佐證 |
| 個管有基礎（社區慈善/災害關懷經驗） | 個案關懷模組沿用訪視語彙：安心膚慰／醫療（人醫會）／轉介／退住轉社區訪視 |
| 空間×餐食×物資整合經驗＝0 | 單一資料源：一次報到六處連動（空間/餐食/物資/警示/儀表板/稽核） |

## 三流設計
- **工作流×4**：據點開設狀態機（待命→整備→申請→核准→運作→縮編→關閉）／收容（報到→篩檢→配位→安置→退住→社區追蹤）／物資請領（申請→核准→出庫→簽收，跨據點加總指揮）／香積日循環（預估→備餐→出餐→回報）。
- **資訊流**：報到單一 reducer 一次改完六處 state 再單次 commit（不存在部分連動的「第二份真相」）；退住反向釋放；UI 以「六氣泡連動摘要」呈現。
- **權限流**：8 角色（總指揮中心／據點指揮／報到組／空間組／香積組／物資組／關懷組／醫療組-人醫會）×集中權限表 `PERM`，所有動作經 `guard()` 統一裁決；越權＝攔截＋toast＋寫入稽核；制度說明頁矩陣由 ROLES/PERM **程式生成**，保證與實際行為一致。

## 模組（8 分頁）
總覽儀表板（角色視角＋燈號警示列）｜據點與空間（含整備檢核）｜報到與住民（money shot）｜個案關懷（含醫療子分欄）｜香積餐食｜物資設備（請領全鏈＋捐贈）｜志工人力（唯讀彙整）｜制度說明（三流圖解＋RACI＋演示動線講稿）。

## 開發流程（本次演示的另一個看點）
規格 v0 → 顧問團平行審（architect／product-designer／qa-strategist，20 項意見全採納、0 分歧）→ PM 收攏為實作指令書 → 實作 → Playwright 50 項自檢 → fresh-context verifier 驗收。顧問團關鍵修正：報到連動改單一 reducer、render 只重繪當前分頁、RBAC 集中權限表、醫療組專屬入口、退住二次確認、志工模組降級唯讀。

## 驗收
- Playwright 文字驗證 **50/50 通過**：375/390/768/1440 四寬度 console 零錯誤、無水平捲動；8 分頁不重複；越權攔截寫稽核；報到 5 口（含糖尿病＋嬰兒）→ 空間+5／晚餐+5（特殊餐各+1）／床毯包各−5／稽核+1；滿床/0 口/重複證號/負庫存全擋；開設核准與重複核准擋；請領全鏈＋跨據點攔截；退住反向＋轉追蹤；localStorage 持久化＋重置。
- fresh-context verifier（opus）獨立驗收：結論見 commit 訊息／回報。

## 設計假設（待 Mason 裁決）
1. **退住物資回補：床回庫、毛毯/盥洗包（消耗品）不回補**——顧問團未言明處的預設值。
2. 餐食預估口徑＝在住人數＋駐點志工；特殊餐由報到健康篩檢欄位自動彙總。
3. 個資最小化：證號/電話僅存遮罩；正式版需驗證與加密。
4. 正式版需中央資料庫＋離線同步（災時斷網常態）；本原型單機 localStorage。
